# ADR-0003: 용어집은 엑셀 업로드 대신 브라우저가 관리한다

- **상태**: 채택됨
- **날짜**: 2026-07-21

## 맥락

용어집은 원래 번역할 때마다 엑셀 파일을 올리는 방식이었다. 용어 하나를 고치려면 파일을 열어 수정하고 다시 올려야 했고, 검토 중에 발견한 용어를 그 자리에서 반영할 방법이 없었다. 파일이 곧 상태여서 "지금 어떤 용어집이 적용 중인가"도 화면에서 알 수 없었다.

동시에 프롬프트 비용 문제가 있었다. 용어집 전체를 모든 배치 프롬프트에 붙이면 용어집이 커질수록 번역 요청마다 토큰이 불어난다.

## 결정

브라우저가 용어집을 소유한다. `localStorage`에 버전이 붙은 용어집 라이브러리를 두고, 앱 안에서 직접 편집하거나 CSV/Excel을 가져온다. 여러 용어집을 동시에 활성화할 수 있고 명시적 순서가 곧 우선순위다. 작업을 시작할 때 활성 항목을 병합해 요청에 스냅샷으로 실어 보내므로, 진행 중인 번역이 나중의 로컬 편집으로 바뀌지 않는다. 검토 중 추가한 용어는 로컬에 저장하면서 `PATCH /api/v1/jobs/{job_id}/glossary`로 현재 작업에 반영한다.

프롬프트에는 **해당 문단 원문에서 실제로 매칭된 용어만** 주입한다. PRE/POST 적용과 스윕은 전체 용어집을 쓴다.

## 결과

- 용어집이 커져도 번역 프롬프트 길이가 그에 비례해 늘지 않는다.
- 활성 용어집이 여러 개일 때 첫 번째 정규화 매칭이 이긴다. 반대 방향 쌍이 서로를 덮어쓰지 못한다.
- 상태가 브라우저에 산다 — 기기 간 동기화가 없고, `localStorage` 용량·손상에 직접 대응해야 한다. 저장 실패는 메모리 상태를 건드리지 않고, 손상된 페이로드는 복구 키로 복사한 뒤 살릴 수 있는 행만 건진다.
- 엑셀 업로드 API 경로는 호환을 위해 남겼다.
- 실사용 용어집은 수백 단어 규모라, 목록 가상화나 스윕 최적화는 하지 않는다.
