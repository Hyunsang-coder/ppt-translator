# ADR-0004: 검토 화면은 타일 그리드 대신 한 건씩 처리하는 큐다

- **상태**: 채택됨
- **날짜**: 2026-07-29

## 맥락

번역 결과 검토 화면은 플래그된 항목을 타일 그리드로 한꺼번에 펼쳐 보여줬다. 어디부터 봐야 할지 화면이 알려주지 않으니 사용자가 스스로 순서를 정해야 했고, `ReviewPanel`은 1,070줄짜리 단일 화면으로 자라 있었다.

## 결정

검토 화면을 큐로 만든다. 왼쪽 레일에 덱의 남은 작업이, 가운데에 정확히 한 건이, 오른쪽에 용어집이 놓인다. "무엇이 한 항목인가"와 "커서가 어디로 가는가"는 `lib/review-queue`에 두고, `ReviewPanel`은 가져오고·바꾸고·그리는 컨테이너로 축소한다.

되돌리기는 클라이언트의 순서 있는 액션 로그를 따른다. 무시(dismissal)는 복원으로, 편집은 `undoReview`로 되돌린다 — 서버의 두 스택은 서로 독립이라 어느 쪽이 마지막이었는지는 클라이언트만 안다.

## 결과

- 항목 수정 후 재조회는 `load()`가 아니라 `refresh()`를 거친다. 스윕 재실행이 화면을 스피너 뒤로 비우지 않는다.
- 검토 상태 판단 로직이 컴포넌트 밖으로 나와 테스트 가능해졌다.
- 전체 덱을 한눈에 훑는 조망은 포기했다. 대신 왼쪽 레일이 남은 작업량을 보여준다.
- 마이그레이션을 단계로 쪼갰다. Phase 1에서는 편집과 부분 일치 시트가 기존 propose → compare → apply 경로를 유지했다 — 여기서 같이 걷어냈다면 Phase 3까지 번역을 고칠 수 없는 화면이 됐을 것이다.
